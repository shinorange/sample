# 既存モデルのレビューとブラッシュアップ

作成済みモデル(自作・他者作・Blockbench 産を問わず)に対する
**レビュー → 改造・改善・修正** の体系。新規作成と違い、既存の UV と
テクスチャという「壊してはいけない資産」があるのが本質的な差。
その保全ルールを軸に手順を組む。

## レビューの手順

依頼が「レビューして」「改善して」「直して」のどれでも、入口は同じ:

```bash
# 1. 自動レビュー(検証+規範チェック+メトリクス)
python3 scripts/review_geo.py model.geo.json --texture model.png --report review.md

# 2. 目視用レンダリング(必ず Read で見る)
python3 scripts/render_geo.py model.geo.json --texture model.png -o before.png
python3 scripts/render_geo.py model.geo.json -o before_flat.png   # 構造確認用
```

出力の読み方:
- **[E]** は無条件で修正対象。**[W]** は「直すか、意図的である理由を
  成果物に明記して残すか」の二択(例: mirror 共有の UV overlap は意図的)。
- **[N] と参考値はレビューの出発点**であって自動修正リストではない。
  頭身比 0.15 は威圧系 MOB なら正解。メトリクスは「設計意図と一致して
  いるか」を判断する材料として使う。
- レポートと目視所見を統合し、**指摘リスト(重要度順)**を作ってから
  手を動かす。ユーザーへの「レビューだけ」の依頼なら、このリストと
  レンダリング画像が納品物になる(勝手に修正まで進めない)。

## レビューの観点

自動チェックが拾えない、目視でしか判断できない項目:

- **シルエット**: front/left/iso の輪郭だけで正体が分かるか。弱い場合、
  原因は大抵「奥行きテーパー不足」か「二次ディテールが輪郭に出ていない」
- **キャラクター性**: 見せ場(顔・尾・発光部)が 1 視点目で目に入るか。
  全部を均等に作り込むと見せ場が消える
- **バニラ整合**: 既存 MOB と並べて浮かないか(彩度・密度・比率。
  vanilla-calibration.md の物差しで確認)
- **面の情報量バランス**: 巨大な単色面(寂しい)/全面ノイズ(うるさい)の
  両極に落ちていないか(texturing.md の 10〜30% ルール)
- **アニメ耐性**: pivot 位置で関節を ±30° 曲げた姿を想像して隙間・
  めり込みが出ないか(animation-rigging.md)
- **改造要求との適合**: 「もっと怖く」「かわいく」等の形容詞は
  比率の言葉に翻訳する(怖く = 頭身を下げ・縦横比を上げ・彩度を落とす、
  かわいく = 頭を大きく・脚を短く・目を大きく離す)

## UV・テクスチャを壊さない編集の三原則

`Model.load()` は既存キューブの UV をピン留めして読み込む。その上で:

1. **移動・回転は無害**: origin/pivot/rotation の変更、
   `translate_subtree()`、ボーンの親変更は UV に一切影響しない。
   プロポーション修正はできる限り移動・回転だけで組む。
2. **サイズ変更は UV 破壊**: size を変えると box UV の展開寸法が変わり、
   既存テクスチャとずれる。どうしても必要なら
   (a) ±0.5 unit 程度なら size を変えず `inflate` で代用する、
   (b) 本当に変えるなら該当キューブの `uv=None` にして `pack_uv()` で
   再配置し、その面だけテクスチャを描き直す。
3. **追加は自動で安全**: 新規キューブは uv 未指定のまま足せば、
   `pack_uv()`/`save()` が既存 UV を避けて空き領域に配置する。
   テクスチャは既存 PNG を開き、`face_rects()` で得た新規矩形
   **だけ**を描き足す(worked-example/refine_fennec.py が実例)。

削除の扱い: キューブ/ボーン削除 (`remove_bone()`) は UV に穴が空くだけで
無害。テクスチャの旧領域は消さなくても表示に影響しない(気になるなら
透明で塗り潰す)。

## 改造レシピ集

いずれも「編集 → `--diff` で確認 → validate → render 目視」をワンセットで。

- **ディテール増強(二次・三次を足す)**: 空き UV を review の
  `texture_free` で確認 → 新規キューブ/板ポリ/殻を追加(uv 自動)→
  新規矩形だけテクスチャ追記。detail-techniques.md の階層配分を再計測。
- **プロポーション修正**: 移動だけで組むのが定石。
  例: 脚を長く見せる → 脚は伸ばさず body 以下を `translate_subtree` で
  +2 上げ、脚キューブを inflate -0.25 で細く。スタンス拡大 → 各脚
  subtree を外へ ±0.25〜0.5。
- **ポーズ・表情の調整**: ボーン rotation の編集のみ(尻尾のカール、
  耳の開き、首の傾げ)。アニメ前提の部位はボーン回転、静的飾りは
  キューブ回転、の区別を維持する。
- **1 本棒 → セグメントチェーン化**(尾・首の品質向上): 旧キューブを
  削除し `segment_chain()` で置換。旧 UV 領域は放置してよいが、新セグメント
  のテクスチャは旧キューブの色を `uv_report` で対応を取りながら移植する。
- **殻レイヤー追加(服・鎧・毛)**: 対象キューブと同じ origin/size で
  inflate +0.25〜0.75 のキューブを追加。z-fight しないこと(inflate 差 ≥0.25)。
- **z-fight 修正**: validate の指摘座標のキューブを 0.1〜0.25 ずらすか
  inflate 差を付ける。「埋まった継ぎ目」指摘は放置してよい。
- **密度違反の修正**: per-face UV の uv_size を面の実寸に合わせる。
  全体を高精細化したい場合はテクスチャ画像だけ 2 倍サイズにする
  (geometry-format.md の HD 方式。UV 座標は不変なので安全)。
- **リグ修正(pivot 移動)**: pivot 変更は UV 無害だがアニメの見た目が
  変わる。既存アニメがあるモデルでは回転テストを再確認。

## before/after の検証ループ

```bash
cp model.geo.json model.before.geo.json          # 退避(必ず)
# ... 編集スクリプト実行 ...
python3 scripts/review_geo.py model.geo.json --diff model.before.geo.json
#   → 変更行が「意図した編集」と 1:1 対応するか確認。想定外の行が
#     出たらその場で原因を潰す(後回しにすると切り分け不能になる)
python3 scripts/validate_geo.py model.geo.json --texture model.png
python3 scripts/render_geo.py model.geo.json --texture model.png -o after.png
```

after.png と before.png を**両方 Read して並べて比較**する。改善点が
画像で説明できない修正は「改善」ではない。ユーザーへの報告には
before/after のレンダリングを添える。

## 他者作モデルを扱うときの注意

- **legacy 1.8 形式**は load が拒否する → Blockbench で 1.12+ に変換して
  もらう(validate_geo がエラーメッセージで案内する)。
- **.bbmodel を渡された場合**: Blockbench で geo.json エクスポートが最短。
  直接読む必要があれば `elements`(キューブ)と `outliner`(ボーン階層)を
  読む — 構造は geo.json と同型でキー名が違うだけ。
- 小数 UV・負サイズ・per-face 混在など**手癖の強いデータ**が普通に来る。
  まず review_geo で実態を把握し、[E] だけ直して挙動を変えない、が初手。
  スタイル(命名・階層)の全面リファクタは依頼されるまでやらない。
- 改造前に必ず元ファイルを `*.before.geo.json` として残す。
