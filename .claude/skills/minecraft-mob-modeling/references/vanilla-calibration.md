# バニラ較正表(サイズ・比率の物差し)

カスタム MOB の寸法は必ずバニラとの相対で決める。「なんとなく大きめ」で
作ると、ゲーム内に置いた瞬間に世界観から浮く。この表を物差しに使う。

数値は較正用の目安(モデルは概数、ヒットボックスは仕様値)。
1 ブロック = 16 units。

## 比率の法則(バニラから抽出した設計規範)

- **頭は全高の 1/4〜1/3**。1/4 = 標準体型(プレイヤー)、1/3 以上 =
  かわいい/子供(村人の頭は縦 10 で存在感増)。恐怖系はむしろ頭を
  小さく(エンダーマン比率 8/46 ≒ 1/6)。
- **脚の太さは胴幅の 1/3〜1/2**。細いほど俊敏・不気味(スケルトン、
  エンダーマン)、太いほど鈍重・愛嬌(クリーパー、ゴーレム)。
- **子供 MOB** はバニラでは「同モデルで頭スケールだけ大きく表示」。
  カスタムで子供版を作るなら 頭そのまま + 胴脚を 60% にする。
- **幅 > 高さ = 非脅威**(豚・スパイダー除く)、**高さ ≫ 幅 = 脅威**
  (エンダーマン・ウィザー)。シルエットの縦横比が敵対性の第一印象を作る。
- ヒットボックスとモデルはだいたい一致させる(モデルがヒットボックスから
  大きくはみ出すと攻撃判定と見た目がズレて操作感が悪い。尾・翼などの
  末端は例外ではみ出してよい)。

## カスタム MOB のサイズ決定手順

1. ゲーム内での役割から高さを決める(家畜: 0.7〜1.4、雑魚敵: 1.7〜2.0、
   エリート: 2.5〜3.0、ボス: 3.5+ ブロック)。
2. 高さ × 16 = 全高 units。アーキタイプ(anatomy-patterns.md)の基準寸法を
   その全高に比例スケールする。
3. **確認**: render_geo.py でプレイヤー(32 units)と並べたつもりで比率を見る。
   scripts の使い方: 自モデルと `demo_humanoid`(geo_builder.py の
   スモークテストで生成可)を同じ scale でレンダリングして横に並べる。
4. ヒットボックス(BP 側 collision_box)をモデル寸法に合わせて宣言する。
