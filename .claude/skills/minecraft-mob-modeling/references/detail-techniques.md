# 精巧モデリング技法集

「精巧」= キューブを増やすことではない。**シルエットが読め、密度が揃い、
細部に階層がある**モデルが精巧に見える。バニラのウォーデンは約 20 キューブで
コミュニティの 200 キューブモデルより精巧に見える。理由がこのファイルの内容。

## 三段階のディテール階層

視覚の重み付けを 3 層に分けて配分する。全部を同じ細かさで作ると
「ノイズの塊」になり、逆に精巧さが消える。

- **一次(体積の 60〜70%)**: 頭・胴・腰。3〜8 個の大きなキューブ。
  ここのプロポーションが 9 割を決める。最後まで動かせるように最初に確定させない
  (ブロックアウト段階で仮置き)。
- **二次(25〜35%)**: 耳・鼻先・顎・尾・肩・腿・足先。一次の箱に**食い込ませて**
  取り付ける(表面に貼ると弱い。1〜2 unit 埋め込むと連続して見え、関節の回転でも
  隙間が出ない)。
- **三次(5%)**: 牙・爪・角・ベルト・ボタン・毛房。0.5〜1 unit 級の小キューブか
  テクスチャで描く。**1 unit 未満の形状は原則テクスチャで表現**(ジオメトリに
  すると密度が壊れる。下記「テクセル密度」参照)。

配分の検算: レンダリングして遠目(縮小表示)で見たとき、三次ディテールが
消えても何のMOBか分かるなら配分が正しい。

## シルエット駆動の作業順

1. **資料**: 実在動物・既存MOBの比率をまず数字にする(頭:胴:脚の長さ比)。
2. **ブロックアウト**: 一次キューブのみで全身を組む。`render_geo.py` の
   front/left ビューで**塗りつぶしシルエットとして**評価する。
   この段階で頭身・重心・脚の太さを決め切る。
3. **二次を追加**して再レンダリング。シルエットの輪郭に「意味のある凹凸」が
   増えたかを確認(輪郭が変わらない二次ディテールは無駄が多い)。
4. **三次・テクスチャ**は最後。
5. 各段階で `validate_geo.py` を通す(後からまとめて直すより安い)。

シルエットの品質基準: 前後・左右・斜めのどこから見ても同じ生き物に見える。
1 方向だけ設計すると横から見たとき「厚みのない看板」になりがち。**奥行き
(Z 方向)のサイズ変化**を意識的に付ける(例: 頭より鼻先を細く、胸より腹を細く)。

## 箱を崩す

単一の大きな箱は「箱」にしか見えない。曲面・テーパーの錯覚を作る定石:

- **段差スタック(ドーム/丸み)**: 大きい箱の上に一回り小さい箱(各辺 -2〜-4
  unit)を 1〜2 段重ねる。3 段以上はバニラらしさを失う。
  例: 亀の甲羅、スライムの頭頂、キノコの傘。
- **前絞りテーパー(顔まわり)**: 頭 8×8×8 に対して鼻先 4×3×3 を -Z に突き出す
  (豚・狼・キツネの文法)。さらに口先端 2×2×1 を足すと三段テーパーになり
  「箱の犬」から「犬」になる。
- **ブラウリッジ(額・眉)**: 頭上前縁に 8×1×2 の薄い箱を +0.25 inflate で重ねる
  と目元に影の段ができ、表情が締まる。
- **面取りの錯覚**: 角に 45° 回転した薄い板を当てるより、**テクスチャの
  角 1 ピクセルを暗くする**方が Minecraft らしく仕上がる。ジオメトリの面取りは
  ボスMOB級のスケールでだけ検討する。
- **関節の丸め**: 肘・膝の位置でキューブを 2 本に分け、互いに 1〜2 unit
  重ねる(オーバーラップ)。曲げアニメーションで隙間が開かず、直立時も
  節として読める。

## セグメントチェーン

尾・首・蛇体・触手・ツタは**等分セグメントの親子チェーン**で作る。

- セグメント数: 尻尾 3〜4、首 2〜3、蛇の胴 5〜8、触手 4〜6。
- 各セグメントは前のセグメントの子ボーンにし、**pivot をセグメントの付け根**に置く。
- 曲げは各ボーンに小さい `rotation` を同方向に積む(1 節 10〜25°)。等角で積むと
  きれいな円弧、先端ほど角度を増やすと「垂れ」、交互に振るとS字になる。
- 先端に向けて断面を 1〜2 unit ずつ絞る(テーパー)と有機的になる。
- `geo_builder.py` の `segment_chain()` がこの構造を一発生成する
  (方向・節数・テーパー・曲げ角を引数で指定)。
- アニメーション時は**根元から先端へ位相を遅らせた**同じ揺れを与えると
  「しなり」になる(references/animation-rigging.md 参照)。

## 板ポリ(厚さ0キューブ)

`size` の 1 軸を 0 にした平面キューブ。両面が描画される。用途:

- 耳の膜・ヒレ・翼膜・葉・たてがみ・ヒゲ・羽飾り・前髪
- アホロートルのエラ、ニワトリの翼端、ファントムの翼が典型例
- テクスチャの**透過(アルファ0)ピクセルで輪郭を自由に切り抜ける**のが最大の
  強み。ギザギザの毛先・裂けた翼・葉脈はジオメトリでなく透過で描く。
  マテリアルを `entity_alphatest` にすること(不透明マテリアルでは黒く出る)。
- 交差配置(X字に 2 枚)で草・炎・ふさふさ感(サボテンの花方式)。
- 弱点: 真横から見ると消える。シルエットの主役には使わず、必ず体積のある
  キューブの補助として使う。厚みが要る羽は 1 unit 厚 + inflate 調整でもよい。

## 重ね着レイヤー(inflate 殻)

本体キューブと同じ origin/size のキューブを重ね、`inflate` だけ変えた殻を作る:

- **服・鎧・毛皮**: inflate +0.25〜+0.5。テクスチャの透過部分から下のレイヤーが
  覗く(ゾンビの服、プレイヤーの外側レイヤーと同じ仕組み)。
- **多重殻**: +0.25(シャツ)、+0.5(コート)のように重ねれば立体的な着衣。
  各殻の UV は独立に取る(自動パッキングなら勝手に確保される)。
- **発光ライン・模様**: 発光マテリアルの殻に模様だけ描く(他は透過)。
- 殻は同じ剛体として動くので関節をまたぐ殻は作らない(袖は腕ボーンの殻、
  裾は胴ボーンの殻と分割する)。
- 負の inflate(-0.25 など)で「本体より少し痩せたインナー」も作れる。

## 微回転

すべてが軸平行だと工業製品に見える。生体感は ±5〜15° の微回転で出す:

- 耳を外側へ 10°、尻尾の付け根を 15° 上げ、牙を 5° 開く、羽先を 8° 反らす。
- **回転は三次ディテールと付け根パーツに限定**する。一次キューブ(胴・頭)を
  傾けるとバニラの文法から外れて「別ゲーの読み込みミス」感が出る
  (例外: 四足獣の首 45°、鳥の尾 30° など機能的な傾き)。
- 角度は 5° 刻み程度に丸めると統一感が出る。22.5° の倍数はブロックモデルと
  調和する角度として特に安全。
- アニメーションで動かす部位はキューブ回転でなく**ボーン回転**で傾けておく
  (初期姿勢もアニメも同じ軸で管理できる)。

## テクセル密度の統一

**モデル 1 unit = テクスチャ 1 px を全キューブで守る。** これが崩れたモデルは
一目で素人くさくなる(部位ごとにドットの大きさが違って見える)。

- box UV は仕組み上ほぼ 1:1 になるので、基本は自動で守られる。壊れるのは
  per-face UV で矩形を拡縮したときと、小数サイズのキューブ。
- 高精細にしたいときは**モデル全体を 2 倍密度**にする: texture_width/height を
  2 倍にし、全 UV も 2 倍領域を使う……のではなく、`texture_width` は据え置きで
  **テクスチャ画像だけ 2 倍サイズ(128×128 で宣言 64×64)にする**のが正道。
  1 unit = 2 px になり全体が均一に細かくなる(バニラ HD テクスチャと同じ方式)。
- 例外的に顔だけ密度を上げたい場合も、まず「2 倍密度 + 他部位を単色気味に塗る」
  で対処する方が安全。

## Z-fighting の予防

同一平面に同じ向きの面が 2 枚重なると描画がチラつく。

- 接して「乗っている」だけ(頭が胴の上、脚が地面)は問題ない。危険なのは
  **面一(つらいち)の重なり**: 本体と同じ面位置に張り付けた飾り、同サイズの
  殻(inflate 0)、左右の脚が中央で密着して側面が一致、など。
- 対策: 飾りは 0.25 unit 浮かす/食い込ませる、殻は必ず inflate を付ける、
  密着する対パーツは 0.1〜0.2 離すか逆に 0.2 重ねる。
- `validate_geo.py` が「z-fight risk」として自動検出する(埋まって見えない
  継ぎ目の警告は無視してよい、と出力にも書いてある)。

## キューブ予算

| 規模 | キューブ数目安 | 例 |
|---|---|---|
| バニラ級シンプル | 6〜20 | クリーパー6、豚7、プレイヤー6(+殻6) |
| バニラ級リッチ | 20〜40 | 狼、キツネ、ウォーデン、スニッファー |
| 精巧カスタム | 40〜120 | ボス、看板MOB |
| 上限の目安 | 〜200 | これ以上は密度が壊れるか描画負荷が問題化 |

- 増やす前に「テクスチャで描けないか」を毎回問う。**テクスチャで描けるものを
  ジオメトリにするのが Minecraft モデリング最大のアンチパターン。**
- キューブが 60 を超えたら、３個以上のキューブに完全に埋まった面を per-face UV
  で削除して描画とテクスチャ領域を回収する(隠れ面カリング)。
- ボーン数はアニメーションの必要数で決める(動かさない三次ディテールは
  親ボーンに直接ぶら下げ、専用ボーンを作らない)。

## 左右対称の運用

- 構造(ボーン・キューブ配置)は左右対称に作り、`mirror` で右の UV を左に
  再利用してテクスチャ領域を半減させるのが基本。
- ただし**完全対称は無機質**。仕上げで非対称を 1〜2 点だけ入れる:
  片耳の折れ、傷、模様のズレ、アクセサリー。非対称にした部位だけ mirror を
  外して独立 UV にする。
- 「構造は対称、テクスチャで 1 点だけ崩す」が費用対効果最高。

## 精巧化チェックリスト

モデル完成宣言の前に全項目を確認:

- [ ] front/left/iso のシルエットだけで何のMOBか分かる
- [ ] 一次:二次:三次の体積配分がおおむね 65:30:5
- [ ] 全キューブのテクセル密度が 1:1(または全体で均一な 2 倍)
- [ ] 頭・鼻先・胴・脚に Z 方向のテーパーがある(真四角の連続になっていない)
- [ ] 関節部でキューブが 1〜2 unit オーバーラップしている
- [ ] 二次パーツが本体に食い込んでいる(表面貼り付けになっていない)
- [ ] validate_geo.py がエラー 0(z-fight 警告は埋没継ぎ目のみ)
- [ ] 微回転が三次ディテールに 2 箇所以上、一次キューブには(機能的理由なしに)ない
- [ ] 尾・首など長物がセグメントチェーンになっている(1 本棒でない)
- [ ] ボーン名と階層がアニメーション想定と一致(animation-rigging.md 参照)
