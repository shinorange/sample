# MOB アーキタイプ別 設計図集

体型の型(アーキタイプ)ごとの、実寸(unit)入りのボーン構成テンプレート。
新しい MOB は必ずどれかの型から出発し、寸法を変形させて個性を出す。
ゼロから寸法を発明すると Minecraft の文法から外れやすい。

数値は「バニラ準拠の出発点」。±20% 程度の変形は文法内。
座標系: Y上・正面-Z・原点足元中央(references/geometry-format.md 参照)。

## ヒューマノイド

プレイヤー/ゾンビ/スケルトン系。全高 32 units(2 ブロック)。

```
root (0,0,0)
└─ body   pivot(0,12,0)   cube(-4,12,-2) 8×12×4
   ├─ head pivot(0,24,0)  cube(-4,24,-4) 8×8×8
   ├─ arm_right pivot(-5,22,0) cube(-8,12,-2) 4×12×4
   ├─ arm_left  pivot( 5,22,0) cube( 4,12,-2) 4×12×4  mirror
root 直下:
   ├─ leg_right pivot(-1.9,12,0) cube(-3.9,0,-2) 4×12×4
   └─ leg_left  pivot( 1.9,12,0) cube(-0.1,0,-2) 4×12×4  mirror
```

- 頭:全高 = 1:4。**かわいくするなら頭を大きく**(1:3 で子供っぽく、1:2.5 で
  マスコット級。村人・ヴェックスは頭でか比率)。
- 細身の変形: 腕脚を 2×12×2(スケルトン)や 3×12×4(プレイヤー slim)に。
- 腕の pivot は肩の高さ y=22(体上端 y=24 の 2 下)。脚 pivot y=12。
  この pivot を守らないと歩行アニメの見た目が壊れる。
- 服・鎧は同寸 + inflate 0.25〜0.5 の殻レイヤーで。

## 小型四足獣

豚キャリブレーション。体高〜14 units、胴が水平の箱。

```
root (0,0,0)
└─ body  pivot(0,9,3)    cube(-5,6,-8) 10×8×16   ※胴は Z に長い
   ├─ head pivot(0,12,-6) cube(-4,8,-14) 8×8×8
   │   └─ (snout) head に直付け cube(-2,9,-15) 4×3×1
   ├─ leg_front_right pivot(-3.5,6,-5) cube(-4.5,0,-6) 4×6×4  ※やや内寄せ可
   ├─ leg_front_left  pivot( 3.5,6,-5) …mirror
   ├─ leg_back_right  pivot(-3.5,6, 5) cube(-4.5,0,4) 4×6×4
   └─ leg_back_left   pivot( 3.5,6, 5) …mirror
```

- 狼・キツネ・猫はこの型の細身版: 胴 6×6〜7×9(断面)×長さ 9〜12、脚 2×8×2、
  頭 6×6×4 + 鼻先 3×3×4、**首下にたてがみ/胸毛キューブ**(狼の 8×6×7)を
  足すと哺乳類らしさが跳ね上がる。
- 頭は胴の前端に 1〜2 unit 食い込ませる。head pivot は首の付け根
  (胴前端の上寄り)に置き、見回し・見下ろしで首が伸びて見えないようにする。
- 尻尾はセグメントチェーン(detail-techniques.md)で 2〜4 節。
- 脚 pivot は**胴の底面より 0〜1 unit 上**(胴に埋めた位置)。歩行で脚が
  胴から離れて見えなくなる。

## 大型四足獣

牛キャリブレーション。体高〜22 units。

```
root
└─ body  pivot(0,17,2)   cube(-6,10,-7) 12×12×14(胴)
   │                     +乳・腹の追加キューブ可
   ├─ head pivot(0,20,-7) cube(-4,16,-13) 8×8×6
   │    ├─ 角: cube(-5,21,-11) 1×3×1 ×2(左右)
   │    └─ 鼻先/口: cube(-3,16,-14) 6×3×1
   ├─ leg_front_right pivot(-4,12,-5) cube(-5,0,-6.5) 4×12×4
   └─ …他 3 本(後脚 pivot z=+4.5)
```

- 馬型はさらに首ボーン(斜め 45° 前傾の 4×12×8)を胴と頭の間に挟む。
  首があるだけで大型獣の風格が出る。
- ラクダ・スニッファー級(体高 28+)は脚を 12〜18 長にし、胴を 2 分割
  (前胴・後胴)すると歩行時に背中がしなる余地ができる。

## 鳥型

ニワトリキャリブレーション。全高〜16 units。

```
root
└─ body  pivot(0,8,0)    cube(-3,4,-3) 6×8×6(前傾 −? 胴はやや前傾配置)
   ├─ head pivot(0,9,-4) cube(-2,9,-6) 4×6×3
   │    ├─ くちばし cube(-2,11,-8) 4×2×2
   │    └─ 肉髯(にくぜん) cube(-1,9,-7) 2×2×2
   ├─ wing_right pivot(-3,11,0) cube(-4,4,-3) 1×4×6
   ├─ wing_left  pivot( 3,11,0) cube( 3,4,-3) 1×4×6  mirror
   ├─ leg_right pivot(-2,5,1) cube(-2.5,0,-2) 3×5×3(脚+足先を含む)
   └─ leg_left  pivot( 2,5,1) …mirror
```

- 翼は**厚さ 1 の縦板**を胴側面に付け、Z 軸回転でパタパタさせる(pivot は
  翼上端の付け根)。
- 大型の鳥・飛行MOBの開いた翼は「腕骨キューブ(2×2×長)+ 翼膜の板ポリ」を
  2〜3 節連ねる(ファントム文法)。
- 尾羽は後方へ 30° 上げた板ポリ扇。

## 魚・水棲型

タラ/サケキャリブレーション。**魚は原点を腹の下端でなく水中姿勢で考える**
(hitbox が小さいので y 0〜 で薄く作る)。

```
root
└─ body pivot(0,0,0)   cube(-1,0,-4) 2×4×8(胴)
   ├─ head cube(-1,0,-7) 2×3×3(前絞り)
   ├─ tail pivot(0,0,4) セグメント1〜2 + 尾ビレ板ポリ 0×4×4
   ├─ fin_top   板ポリ cube(0,4,-1) 0×2×4(背ビレ、X=0 の縦板)
   └─ fin_right/left 板ポリ 或いは 22.5° 回転の胸ビレ
```

- ヒレは全部板ポリ + 透過テクスチャ。背ビレは X=0 面の縦板、胸ビレは
  Y 回転 ±30° で開く。
- アホロートル文法: 胴 8×4×10 の低い箱 + 頭 8×5×5 + エラ板ポリ 3 対 +
  短足 3×1×2 ×4。「低くて幅広」が水棲哺乳類・両生類の記号。
- イカ・タコ: 頭部の大箱 + 触手はセグメントチェーン ×8。

## 蛇・多節型

```
root
└─ seg_0 pivot(0,2,-8) cube 4×4×6   ← 頭側
   └─ seg_1 pivot(0,2,-2) …
      └─ seg_2 … (5〜8 節、後方 +Z へ)
head は seg_0 の子として 5×4×6(胴よりわずかに太く)
```

- 節ごとの Y 回転でとぐろ・蛇行を静的ポーズとして作れる。
- 地這いは全 pivot y を低く(胴断面の中心 y=2)。鎌首は seg_0〜1 の X 回転。
- シルバーフィッシュ文法: 節ごとに高さ・幅を変えた 7 連箱 + 背のトゲ板ポリ。

## 節足型

クモキャリブレーション。

```
root
└─ body pivot(0,9,0)
   ├─ head    cube(-4,4,-11) 8×8×8(前)
   ├─ thorax  cube(-3,6,-3) 6×6×6(中)
   ├─ abdomen cube(-5,4,3) 10×8×12(後)
   └─ leg_r0..r3 / l0..l3  pivot(±2,9,z) cube 16×2×2
        Y回転 ±(20〜50°) + Z回転 ∓(15〜35°) で放射状に展開
```

- 脚は「長さ 16 の水平棒を pivot 根元で Y+Z 回転」がバニラ文法。関節付きに
  精巧化するなら 8×2×2 を 2 節(腿を Z 上げ、脛を Z 下げ)にする。
- 昆虫(ミツバチ文法): 丸みは段差スタック、羽は半透明でなく**透過穴あき板ポリ**
  + 高速羽ばたきアニメで表現。触角は 1×1×3 の微小キューブ 2 節。

## 浮遊飛行型

- **ガスト文法**: 16×16×16 の大箱 + 触手(2×n×2 チェーン)×9。浮遊MOBは
  接地脚がない分、**下面にディテール**(触手・根・結晶)を必ず付ける。
  下から見上げられるMOBだから。
- **ブレイズ文法**: コア(頭)+ 周回する浮遊パーツ(2×8×2 ×12)。浮遊パーツは
  本体と別ボーンにして Y 回転アニメで公転させる。
- ヴェックス文法: ヒューマノイド上半身 + 下半身を尾状の 1 キューブに置換。

## ボス・大型モンスター

- まず**プレイヤーとの対比スケール**を決める(全高 48=3 ブロック: 威圧、
  64=4: ボス級、128+: レイドボス)。レンダリングに 32 unit のヒューマノイドを
  並置して比較するとよい(examples の手法参照)。
- 大型化すると 1:1 密度では面がスカスカになる → **2 倍密度テクスチャ**
  (geometry-format.md)をボスの標準にする。
- 部位数はアーキタイプの合成で増やす: ウィザー = 頭×3 + 肋骨、
  エンダードラゴン = 大型四足 + 翼 + 多節首尾。**「既存型の合成」**が
  Minecraft らしい怪物設計の王道で、完全新規シルエットより強い。
- 破壊可能部位・コア露出などゲーム的ギミックがあるなら部位ごとに
  ボーンを分けておく(後からの分割は UV が崩れる)。

## 共通ボーン階層規約

すべてのアーキタイプで守る規約(アニメーション互換とスクリプト検証のため):

- ルートは `root` (pivot 0,0,0)。全体移動・ジャンプ・死亡転倒は root で行う。
- 頭は必ず `head` という名前にする(Bedrock の look_at 系アニメ・
  ヘルメット装着位置が head 名を前提にする)。
- 左右パーツは `_left` / `_right` サフィックス。多脚は `leg_r0`〜 の連番。
- 階層は「動きが伝播する順」: body → head/limbs、seg_0 → seg_1 → …。
  地面基準で独立に動く脚は body でなく root 直下でもよい(ヒューマノイド脚)。
- 動かさない飾りに専用ボーンを作らない(最寄りの可動ボーンに直付け)。
- pivot は関節の回転中心に置く。「キューブの中心」に置くのは間違い
  (肩は腕上端、顎は顎の後端、尾は付け根)。
